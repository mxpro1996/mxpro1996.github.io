在现代多核（SMP）架构下，编写并发代码本质上是在处理一场由物理电信号驱动的“绩效狂欢”。当我们剥开 mutex_lock 的华丽外衣，最深处只有那几行冷酷的 ldrex/strex。

本文旨在将 Linux 内核的并发体系按“细粒度”与“上下文”进行垂直排布，揭示从物理重试到逻辑认怂的完整链路。

一、 物理原点：指令级的“博弈”

所有的并发逻辑都坍缩在 CPU 的**独占监视器（Exclusive Monitor）**上。这是数字世界的“因果律”起点。

机制 行为本质 绩效代价
ldrex / strex 盲目尝试。在 L1/总线上打标，不成功便成仁。 频繁冲突会导致微指令自杀重试（Re-exec）。
Memory Barrier 压制乱序。强行插入显式依赖（DEP），禁止 CPU 抢跑。 破坏流水线流水，换取语义合规。

底层觉悟：add eax, 1 可能会失败 100 次。你看到的成功，只是在物理竞速中活下来的“幸存者偏差”。

二、 逻辑骨架：原子变量与顺序锁

当物理指令被封装成 C 语言接口，它就成了支撑整个内核的脊梁。

1. atomic_t (原子变量)

  • 本质：基于 ldrex 的无限复读机。
  • 逻辑：只要硬件返回失败，就 while 循环重试。
  • 场景：引用计数、简单的状态位。

2. Seqlock (顺序锁)

  • 本质：软件级 ldrex。
  • 逻辑：乐观赌徒。读者不阻塞，读完检查序号；如果写者动了（序号变了），就推倒重读。
  • 代价：读者可能读到中间态的“毒药”数据。

三、 秩序分配：自旋锁的“取号机”

为了解决原子变量导致的无序践踏，内核引入了“公平排队”机制。

Spinlock / RWLock

  • 底层：atomic_t (取号) + while (叫号)。
  • 同步语义：带出了原子上下文。通过关闭当前核抢占（IRQ），防止“家贼”（本核中断）导致死锁。
  • 物理表现：原地踏步。消耗 100% 的 CPU 功耗，换取纳秒级的响应。

四、 资源让渡：名单管理与调度

当自旋（原地踏步）的成本太高（如磁盘 IO），我们需要物理上让出执行单元（EU）。

Wait Queue (等待队列)

  • 本质：生死簿。由一个 spinlock_t 保护的双向进程链表。
  • 功能：挖出睡眠。它不负责锁逻辑，只负责记下你的名字，并配合 schedule() 让你消失在 CPU 视野里。
  • 地位：它是所有高级阻塞锁（Mutex/Sem）的“户籍办”。

五、 官僚体系：高级锁策略

这是开发者最常触碰的层级，也是最精明的“绩效管理”层。

1. Semaphore (信号量)

  • 逻辑：老牌会计。atomic_dec 发现没坑了，直接叫你去 Wait Queue 领表睡觉。

2. Mutex (互斥锁)

  • 逻辑：极度功利的经理。
    • Fast Path: 尝试 atomic_cmpxchg，成功则零开销。
    • Mid Path: 抢不到先不睡，原地乐观自旋几圈，赌对方快放手了。
    • Slow Path: 实在没戏，才去 Wait Queue 登记睡觉。

六、 终极审计：并发原语频谱

层级 代表机制 底层依赖 行为本质 上下文限制
第一级：指令 ldrex/strex 物理监视器 抢排名，输了重赛 无
第二级：变量 atomic_t while + 指令 撞大运的复读机 无
第三级：自旋 spinlock atomic + 叫号 原地踏步，禁止抢占 禁止睡眠
第四级：名单 waitqueue list + spin 登记名字，准备跑路 进程/中断
第五级：策略 mutex/sem atomic + waitq 抢不到就回家睡觉 禁止中断
第六级：隔离 RCU 屏障 + 指针替换 时空隔离，读写分离 读者极快

结语

在 SMP 的宇宙里，所有的“有序”都是由“无序”最后给出的排名。

  • 追求效率：尽可能停留在 第二级 (Atomic)。
  • 处理驱动：停留在 第三级 (Spinlock)。
  • 业务逻辑：信任 第五级 (Mutex)。

既然所有的上下文最终都基于 ldrex/strex，那么优秀的并发程序，其实就是在**“放任 CPU 瞎跑”与“强迫 CPU 认怂”**之间，寻找那个最完美的 DEP（依赖）平衡点。
